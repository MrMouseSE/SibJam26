# 🧭 Гайд — Добавление новой фичи

↑ [[Паттерны]]

Сквозной рецепт: как добавить новую игровую систему в проект от скелета модуля до wiring на сцене. Все примеры — по реальным идиомам проекта.

## Шаг 0. Определить границы
- Что фича делает и в каких `GameStates` активна.
- Нужны ли ей объекты сцены (тогда понадобится `Container`).
- Какие данные читает (существующий `Description` или новый).

## Шаг 1. Скелет модуля
Папка: `Assets/Scripts/GameSystemsScripts/<Кластер>/MyFeatureScripts`. Минимум три класса.

**Component** — только данные:
```csharp
public class MyFeatureComponent
{
    public MyFeatureContainer Container;   // если нужен объект сцены
    public bool IsButtonPressedThisFrame;  // флаги-триггеры живут здесь
}
```

**Mechanic** — поведение, реализует `IGameMechanic`:
```csharp
public class MyFeatureMechanic : IGameMechanic
{
    public MyFeatureComponent Component;

    public MyFeatureMechanic(MyFeatureComponent component) => Component = component;

    public void SetContainer(MyFeatureContainer container)
    {
        Component.Container = container;
        Component.Container.SomeButton.OnButtonPressed += OnPressed;   // подписка
    }

    private void OnPressed() => Component.IsButtonPressedThisFrame = true;

    public void UpdateMechanic(GameSystemsHandler handler, float deltaTime)
    {
        if (!Component.IsButtonPressedThisFrame) return;
        Component.IsButtonPressedThisFrame = false;

        // ... доменная логика ...

        handler.StateSystem.Mechanic.ChangeState(GameStates.NextState);  // переход дальше
    }

    public void DisposeMechanic()
    {
        if (Component.Container != null)
            Component.Container.SomeButton.OnButtonPressed -= OnPressed; // ОБЯЗАТЕЛЬНО отписаться
    }
}
```

**System** — оркестрация, реализует `IGameSystem`:
```csharp
public class MyFeatureSystem : IGameSystem
{
    public MyFeatureComponent Component;
    public MyFeatureMechanic Mechanic;

    public MyFeatureSystem(/* SomeDescription desc */)
    {
        Component = new MyFeatureComponent();
        Mechanic = new MyFeatureMechanic(Component);
    }

    public void Initialize(GameSystemsHandler handler) { /* стартовая подготовка */ }

    public void UpdateSystem(GameSystemsHandler handler, float deltaTime)
    {
        if (handler.StateSystem.Component.CurrentGameState != GameStates.MyState) return; // гейт по стейту
        Mechanic.UpdateMechanic(handler, deltaTime);
    }

    public void DisposeSystem() => Mechanic.DisposeMechanic();
}
```

## Шаг 2. Регистрация в composition root
В `LoadGameComponent.Awake()` (`GameStartupScripts`) добавить строку рядом с остальными `AddGameSystem`. Порядок регистрации = порядок обхода в update-цикле, поэтому ставить с учётом зависимостей (например систему-модификатор — перед потребителем):
```csharp
_gameSystemsHandler.AddGameSystem(new MyFeatureSystem(/* MyDescription */));
```
Если фиче нужен новый `Description` — добавить публичное поле-ассет в `LoadGameComponent` и прокинуть в конструктор системы.

## Шаг 3. Стейты
- Если фича вводит новый этап — добавить элемент в `enum GameStates` (`GameScripts/GameStates.cs`) и встроить в цепочку переходов (кто переводит «в» и «из»). Подробнее — нода `Стейт-машина GameStates`.
- В `UpdateSystem` фильтровать по своему стейту (см. Шаг 1).
- Переход дальше — `handler.StateSystem.Mechanic.ChangeState(GameStates.X)` (просто пишет `Current`/`Previous`, без событий).

## Шаг 4. Привязка объектов сцены (если нужен Container)
1. Создать `MyFeatureContainer : MonoBehaviour` со ссылками на Unity-объекты (кнопки, аниматоры, рендеры).
2. Положить компонент на объект игровой сцены, проставить ссылки в инспекторе.
3. Добавить поле контейнера в scene-композицию `GameSystemContainer` (`ScenesOperatingScripts`).
4. В `GameSystemContainer.InitializeSceneSystems(...)` дописать wiring:
```csharp
var myFeature = (MyFeatureSystem)systemsHandler.GetGameSystem(typeof(MyFeatureSystem));
myFeature.Mechanic.SetContainer(MyFeatureContainer);
```
Системы постоянны, а контейнеры приходят из активной сцены — отсюда отдельный шаг связывания.

## Шаг 5. Создание игровых объектов
Только через статическую фабрику в `Assets/Scripts/GameObjectFactories` (нельзя `Instantiate` в системах/механиках). Конфиг фабрики — статическим полем на старте, как `StaticElementFactory.CoffeeDescription`.

## Шаг 6. Dispose
- `DisposeSystem` → `DisposeMechanic`.
- В `DisposeMechanic` отписаться от всех событий контейнеров и отменить запущенные `CancellationTokenSource` анимаций.

## Конвенция анимаций (AwaitAnimation)
Если этап сопровождается анимацией, не переходи в следующий стейт сразу. Принятый в проекте паттерн:
1. Запустить логику, перевести игру в `GameStates.AwaitAnimation` (чтобы другие системы «замерли»).
2. Проиграть анимацию через `UniTaskAnimationLazyObject` (длительности брать из `AnimationsDescription` у `GameSpeedSystem`).
3. По колбэку `AnimationCompleted` сделать реальный `ChangeState(GameStates.NextState)` и отписаться от колбэка.
```csharp
animationObject.AnimationCompleted += OnFinished;
// ...
private void OnFinished(UniTaskAnimationLazyObject anim)
{
    anim.AnimationCompleted -= OnFinished;
    _handler.StateSystem.Mechanic.ChangeState(GameStates.NextState);
}
```

## Чек-лист ревью
1. Разделение `System / Mechanic / Component` (+ `Container` при объектах сцены)?
2. Система зарегистрирована в `LoadGameComponent` в нужном порядке?
3. `UpdateSystem` гейтит логику по `CurrentGameState`?
4. Переходы стейтов явные, без тупиков; анимационные — через `AwaitAnimation` + колбэк?
5. Все Unity-ссылки в контейнере, прокинуты в `GameSystemContainer`?
6. Объекты создаются только через `GameObjectFactories`?
7. Есть `Dispose`: отписки от событий и отмена токенов?
8. Обновлены ноды карты (новая система → нода `Система — ...`, при новом стейте — `Стейт-машина GameStates`)?

> [!note] Подводные камни проекта: не менять состав `GameSystems` во время update-цикла (обход словаря в кадре); `GameOver` сейчас никем не выставляется; помни про порядок регистрации систем при межсистемных зависимостях через `GetGameSystem`.
